# Activity files

`core/activityfile` (`:core-activityfile`) reads FIT, GPX, TCX and Shearwater dive (XML) files, optionally gzipped, into an `ImportedActivity`, which `ActivityDraft.fromImport` publishes like a recording (GPX track blob). Every sample's channels (indoor ones too, plus gear changes) become `ImportedActivity.streams` through `StreamBuilder`, in the lexicon's integer units; a phone recording gets distance, altitude and speed streams from `StreamBuilder.fromLocations`. They publish as a `feed.activityStreams` record under the activity's rkey (see `ActivityStreamsStore`). `ActivityFileReader` is the entry point: it picks the format from the content, not the file name. GPX, TCX and Shearwater XML parse in common code with xmlutil's pull parser (`walkXml` matches local names, so namespace prefixes don't matter). Shearwater times have no zone: they're read in the device's zone (`TimeZones.device()`), `ImportedActivity.localStart` keeps the clock, and the import screen warns and lets the athlete pick the dive's zone (`inZone`; web bundles `@js-joda/timezone` for the zone rules). A dive's depths, gases, CNS, tanks and site come through as `ImportedDive`, from Shearwater files and FIT dive logs alike, which only the import screen shows so far. Each FIT decoder passes its SDK's dive messages through as `FitDiveMessages`, and `FitDives` (common) picks the session's summary and the gases breathed. FIT uses Garmin's own SDK on each platform behind the `FitDecoder` interface: the Java SDK on Android, desktop and the AppView (`commonJvmMain`), the npm JS SDK on web (`@JsModule` externals), and the Swift SDK on iOS. Kotlin/Native can't call Swift, so `iosApp/iosApp/SwiftFitDecoder.swift` implements the interface and `ContentView` passes it into `IosAppGraph.Factory`. `gunzip` is expect/actual over each platform's built-in inflater. Every format decodes to a `DecodedActivity`, and `DecodedActivityMapper` (common) interprets it.
