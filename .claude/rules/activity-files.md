# Activity files

`core/activityfile` (`:core-activityfile`) reads FIT, GPX, TCX and Shearwater dive (XML) files and UDDF and Subsurface (`.ssrf`/XML) logbooks, optionally gzipped, into `ImportedActivity`s (`ActivityFileReader.read` returns a list: one per file, or one per dive in a logbook), which `ActivityDraft.fromImport` publishes like a recording (GPX track blob). Every sample's channels (indoor ones too, plus gear changes) become `ImportedActivity.streams` through `StreamBuilder`, in the lexicon's integer units; a phone recording gets distance, altitude and speed streams from `StreamBuilder.fromLocations`. They publish as a `feed.activityStreams` record under the activity's rkey (see `ActivityStreamsStore`). `ActivityFileReader` is the entry point: it picks the format from the content, not the file name. GPX, TCX, Shearwater, UDDF and Subsurface XML parse in common code with xmlutil's pull parser (`walkXml` matches local names, so namespace prefixes don't matter); the dive logs share `DiveLogs` (summary, sub-sport, device name, gases) and skip an undated dive rather than fail the logbook. Dive-log times have no zone (`parseLocalDateTime`): they're read in the device's zone (`TimeZones.device()`), `ImportedActivity.localStart` keeps the clock, and the import screen warns and lets the athlete pick the dive's zone (`inZone`; web bundles `@js-joda/timezone` for the zone rules). A dive's depths, gases, CNS, tanks and site come through as `ImportedDive`, from Shearwater files and FIT dive logs alike, which only the import screen shows so far. Each FIT decoder passes its SDK's dive messages through as `FitDiveMessages`, and `FitDives` (common) picks the session's summary and the gases breathed. FIT uses Garmin's own SDK on each platform behind the `FitDecoder` interface: the Java SDK on Android, desktop and the AppView (`commonJvmMain`), the npm JS SDK on web (`@JsModule` externals), and the Swift SDK on iOS. Kotlin/Native can't call Swift, so `iosApp/iosApp/SwiftFitDecoder.swift` implements the interface and `ContentView` passes it into `IosAppGraph.Factory`. `gunzip` is expect/actual over each platform's built-in inflater. Every format decodes to a `DecodedActivity`, and `DecodedActivityMapper` (common) interprets it. A logbook of several dives shows on the import screen as a `DiveBatch` to pick from (all selected at first, one zone for the file), and `ActivityRepository.publishAll` queues the picked dives before draining the outbox once.

**Duplicate dives.** The import screen loads the athlete's dives from a day either side of the file's (`FeedRepository.ownActivitiesStartedBetween`: the AppView's `getAuthorActivitiesByStart` plus outbox writes it hasn't indexed) and `DiveMatcher` (`core/data`) flags each imported dive that overlaps a logged one by half the shorter, is the same length a whole number of hours off (a zone mix-up), or repeats an earlier dive in the file. Duplicates start on `DuplicateAction.Ignore` (unchecked; Select all skips them) with a warning, and the athlete can import anyway, `Merge` into the logged dive (`ActivityRepository.mergeInto`, `ActivityMerge`: fills only fields and stream channels it lacks; an outbox-pending activity gets only its record merged; picking Merge loads the logged dive's streams so the note says whether charts are added, and `FeedRepository.rewrites` shows the merged record over the AppView's until Jetstream brings it), or `Group` it as another recording (`feed.activity#recordingOf`, an at-uri, so feeds show the dive once and its page lists the recordings). A recording of an in-file dive publishes after it, pointing at its URI.
