# Local ATProto stack

- Data flows PDS → relay (indigo) → Jetstream → AppView. Jetstream bootstraps from the relay's `listHosts`/`listRepos`, so it can't read a PDS directly.
- The PDS serves HTTP only when `PDS_HOSTNAME=localhost`, so the relay and Jetstream use `network_mode: "service:pds"` and their ports are published on the `pds` service. Keep it that way: what DID docs say (`localhost:2583`) has to resolve inside Docker too.
- The relay and Jetstream are built from pinned commits with one-line `sed` patches that relax their SSRF guards for `localhost`. Each `sed` is followed by a `grep -q` of the result, so a drifted target fails the build instead of silently not patching. To bump `INDIGO_COMMIT` or `JETSTREAM_COMMIT`, re-check that the patched file and line still exist upstream at the new commit and update both the `sed` and the `grep`.
- The PDS (`pds.Dockerfile`) is Bluesky's atproto Spaces alpha (`ghcr.io/bluesky-social/atproto:pds-spaces-alpha`), pinned by digest because the alpha breaks things under the same tag. The pin is the Oct 29 alpha (built 2026-10-29, `0.0.0-spaces-alpha-20261029171913`): one `policy` per space (`com.atproto.space.createSpace`, with `personalspace`, `memberspace` and `managedspace` policies) instead of `simplespace`, plus the Oct 22 protocol (credentials bound in the request body, `Atproto-Space-Credential`, and MAC'd reads keyed by each account's `#atproto_kem`).
  - **amd64 only.** Compose runs it with `platform: linux/amd64`, under Rosetta on Apple Silicon. It still becomes healthy in about 10 s.
  - **Runs as `node`.** It's the atproto monorepo (`/app/packages/...`), not the `pds` distribution image. So the Dockerfile patches as `USER root` and creates `/pds` owned by `node`; without that, a fresh volume fails with `SQLITE_CANTOPEN`.
  - **CSRF patch.** The same kind of checked `sed` makes the OAuth CSRF cookie non-Secure, because WebKit drops Secure cookies on `http://localhost` and iOS sign-in then fails with "Missing CSRF header". A `find` must match exactly one `oauth-provider/dist/router/assets/csrf.js`.
  - **Blob limit.** The image accepts uploads up to 5 MiB by default; compose sets `PDS_BLOB_UPLOAD_LIMIT` to 10 MiB so a `feed.activityTrack` or `feed.activitySource` blob at its lexicon's 10 MB `maxSize` fits. A real PDS may set less: the outbox then drops an oversized original rather than retrying it.
  - **Bumping.** Re-check the patch path and its `secure: true,` line, wipe the volumes (schemas change without migrations, and accounts created on an older alpha may lack keys a newer one needs, like `#atproto_kem`), and run `docker/scripts/spaces-smoke.sh alice` and `docker/scripts/syncer-smoke.sh alice --blob`. The built `@atproto/*` packages are in the image (`/app/packages/<name>/dist`); `docker run --entrypoint node` with a mounted script regenerates test vectors, since the alpha's npm packages don't install outside the monorepo.
- Spaces' managing-app callout (`checkUserAccess`) goes from the PDS to the AppView's `did:web`, which only resolves to the AppView through the `scripts/dev.sh` tunnel. `did:web:localhost%3A8081` is the PDS container itself. A tunnel restart changes that DID, so spaces created earlier name a managing app that no longer answers. Recreate them, since local space data is throwaway.
- **Lexicon authority.** OAuth grants a `space:` scope only if the PDS resolves the space type's lexicon. Locally `PDS_LEXICON_AUTHORITY_DID` (in `docker/.env`, empty in `.env.example`) names `lexicons.test`, whose `com.atproto.lexicon.schema` records `docker/scripts/publish-lexicons.sh` writes from `lexicons/**.json` (space types only). `scripts/dev.sh` runs it on every `up`. A new account's DID gets written to `.env`, followed by a full `compose up -d`; `up -d pds` alone would leave the relay and Jetstream in the old container's network namespace. The PDS caches failed lexicon lookups for 5 minutes, and keeps a resolved declaration in its `account.sqlite` (`lexicon` table) across restarts, granting new sessions' `space:` scopes from that copy; the script drops the copies of what it publishes, so a newly declared collection reaches the next sign-in.
- **Labeler (Ozone).** `ozone` runs the upstream image pinned by digest, in the PDS's network namespace (port 3010, published on `pds`), because its DID document names `http://localhost:3010` and both the PDS (proxying `createReport` for `atproto-proxy: <did>#atproto_labeler`) and the host's AppView (`subscribeLabels`) must reach it there. Its database is a second one, `ozone`, on `appview-db`. `docker/scripts/setup-labeler.sh` (run by `scripts/dev.sh`, safe to rerun) creates `moderation.test` (the service account), `mod.test` (an admin moderator) and `triage.test` (the AppView's member), generates `OZONE_SIGNING_KEY_HEX` (secp256k1), adds `#atproto_labeler` and `#atproto_label` to `moderation.test`'s DID document with a PLC operation signed by the PDS's rotation key (run with `node` in the Ozone image, which carries `@did-plc/lib`), writes `OZONE_SERVER_DID` to `docker/.env` and the labeler DID to `local.properties` (`activitytracker.labelerDid`). Until `OZONE_SERVER_DID` is set the container idles instead of crash-looping.
  - **No local UI.** The image's Next.js UI has `plc.directory` and Bluesky's handle resolver compiled in, so it can't sign in to `.test` accounts. Moderate through the API with Basic auth `admin:$OZONE_ADMIN_PASSWORD` (`tools.ozone.moderation.emitEvent`, `tools.ozone.team.addMember`); the `local-stack` skill has the calls.
  - **Team members** must have a full atproto account document (a handle and an `#atproto_pds`): Ozone verifies service auth with `resolveAtprotoData`. The AppView's `did:web` has no PDS, so it joins as `triage.test` instead (`roleTriage`), whose app password `setup-labeler.sh` writes to `docker/.env` (`APPVIEW_TRIAGE_DID`, `APPVIEW_TRIAGE_PASSWORD`) for the AppView's run task.
  - **Bumping.** Pull the new image and pin its digest; Ozone migrates its database at start (`OZONE_DB_MIGRATE=1`). Then rerun `setup-labeler.sh` and the `local-stack` skill's labeler checks. The daemon (`service/daemon.js`: event push to PDSes, scheduled actions) isn't run.
- Public requestCrawl rejects `localhost`, so the `relay-crawl` one-shot registers the PDS through the relay admin API (`admin:$RELAY_ADMIN_PASSWORD`).
- `docker/.env` holds dev-only secrets and is git-ignored. `.env.example` is the template, so add new variables there.
- `create-account.sh` hard-codes the `app.activitytracker.actor.profile` NSID. Keep it in step with `Nsid.NAMESPACE`.
