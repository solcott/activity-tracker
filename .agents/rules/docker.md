# Local ATProto stack

- Data flows PDS → relay (indigo) → Jetstream → AppView. Jetstream bootstraps from the relay's `listHosts`/`listRepos`, so it can't read a PDS directly.
- The PDS serves HTTP only when `PDS_HOSTNAME=localhost`, so the relay and Jetstream use `network_mode: "service:pds"` and their ports are published on the `pds` service. Keep it that way: what DID docs say (`localhost:2583`) has to resolve inside Docker too.
- **Device mode** (the normal setup; physical phones need it) sets `PDS_HOSTNAME` to a public hostname behind a named Cloudflare tunnel, plus `RELAY_CRAWL_HOST` (the bare hostname, which the relay crawls over `wss`) and `PDS_INVITE_REQUIRED=true`. `scripts/dev.sh` writes all three to `docker/.env` from `activitytracker.deviceHost` and empties them without it, and compose defaults each to the localhost value. It reads the host as Gradle does: the Gradle user home's `gradle.properties` (one setting for every checkout and worktree) wins when it has the key, else `local.properties`. In device mode every client uses the public hosts (`GeneratedNetworkConfig`), the builds derive the AppView's public URL from the host (`appview-<host>`, so `dev.sh` keeps no `appviewPublicUrl` in `local.properties`), and the AppView accepts no extra `localhost` audience. The tunnel's ingress file is `~/.cloudflared/activitytracker-dev.yml` (`dev.sh` moves an old `.dev/cloudflared-device.yml` there), so every checkout drives the same tunnel. The stack is one compose project shared by every checkout, so `dev.sh` takes the mode its volumes were made under from the PDS container's `PDS_HOSTNAME` (falling back to `docker/.env` when the container is gone), not from the checkout's copy of `docker/.env`. The PDS's URL is then `https://<host>` (the image takes no port), and the relay, Jetstream and the AppView follow DID documents out through Cloudflare and back in through the tunnel. Those are public addresses, so the localhost patches below go unused but stay for localhost mode. Accounts embed the hostname, so switching modes wipes the volumes (`dev.sh --reset`); a new worktree in the same mode doesn't. The account scripts mint an invite code through the admin API when the PDS asks for one (`docker/scripts/invite-code.sh`). No tracked file names a real device host: use `example.com` in docs.
- The relay and Jetstream are built from pinned commits with one-line `sed` patches that relax their SSRF guards for `localhost`. Each `sed` is followed by a `grep -q` of the result, so a drifted target fails the build instead of silently not patching. To bump `INDIGO_COMMIT` or `JETSTREAM_COMMIT`, re-check that the patched file and line still exist upstream at the new commit and update both the `sed` and the `grep`.
- The PDS (`pds.Dockerfile`) is Bluesky's atproto Spaces alpha (`ghcr.io/bluesky-social/atproto:pds-spaces-alpha`), pinned by digest because the alpha breaks things under the same tag. `pds.Dockerfile`'s header names the pinned release. It names spaces only as `at:space/{did}/{type}/{skey}` (records in them with `/{repo}/{collection}/{rkey}` after), refusing the old `at://{did}/space/...` form everywhere, and refuses app-password sessions on space methods (the scripts sign in with the account password). It speaks `authorizeSpaceSync` (its `notify` registers a syncer for `notifySpaceUpdate`, confirmed with `confirmRegistration` and authenticated by the syncer's token, not service auth), `managedspace.checkAccess` answering `{read, write}`, read MACs as RFC 9421 `hmac-sha256` signatures (`Accept-Signature`, `Atproto-Space-Commit`/`-Record`) keyed by HPKE secret export, STAR archives framed with control bytes, `RepoTakendown`/`RepoDeactivated` for a suspended authority, one `policy` per space (`com.atproto.space.createSpace`, with `personalspace`, `memberspace` and `managedspace` policies), credentials bound in the request body (`Atproto-Space-Credential`), and MAC'd reads keyed by each account's `#atproto_kem`.
  - **amd64 only.** Compose runs it with `platform: linux/amd64`, under Rosetta on Apple Silicon. It still becomes healthy in about 10 s.
  - **Runs as `node`.** It's built from the atproto repo's root `Dockerfile`: the server runs from `/app/services/pds`, and every package, `@atproto/*` included, is under its `node_modules/.pnpm`. The Dockerfile patches as `USER root` and creates `/pds` owned by `node`; without that, a fresh volume fails with `SQLITE_CANTOPEN`. Scripts that run `node` in the container (`publish-lexicons.sh`, `setup-labeler.sh`) do so from `/app/services/pds/node_modules/@atproto/pds`, where its dependencies (`better-sqlite3`) resolve.
  - **CSRF patch.** The same kind of checked `sed` makes the OAuth CSRF cookie non-Secure, because WebKit drops Secure cookies on `http://localhost` and iOS sign-in then fails with "Missing CSRF header". A `find` must match exactly one `oauth-provider/dist/router/assets/csrf.js`.
  - **Blob limit.** The image accepts uploads up to 5 MiB by default; compose sets `PDS_BLOB_UPLOAD_LIMIT` to 10 MiB so a `feed.activityTrack` or `feed.activitySource` blob at its lexicon's 10 MB `maxSize` fits. A real PDS may set less: the outbox then drops an oversized original rather than retrying it.
  - **Bumping.** Re-check the patch path and its `secure: true,` line, wipe the volumes unless the release says its databases migrate (the 2026-11-24 image migrates its own on start; earlier ones changed schemas without migrations, and accounts created on an older alpha may lack keys a newer one needs, like `#atproto_kem`), and run `docker/scripts/spaces-smoke.sh alice` and `docker/scripts/syncer-smoke.sh alice --blob`. The built `@atproto/*` packages are in the image (`/app/services/pds/node_modules/.pnpm/@atproto+<name>@…/node_modules/@atproto/<name>/dist`); test vectors regenerate either with `docker run --entrypoint node` and a mounted script, or from npm, installing `@atproto/space` and `@atproto/crypto` at the release's exact version (from the 2026-11-24 release the alpha packages pin each other exactly, so no `overrides` are needed).
- Spaces' managing-app callout (`checkAccess`) goes from the PDS to the AppView's `did:web`, and the syncer's registration callbacks (`confirmRegistration`, `notifySpaceUpdate`) to its public URL; both reach the AppView only through the `scripts/dev.sh` tunnel. `did:web:localhost%3A8081` is the PDS container itself. A tunnel restart changes that DID, so spaces created earlier name a managing app that no longer answers. Recreate them, since local space data is throwaway.
- **Lexicon authority.** OAuth grants a `space:` scope only if the PDS resolves the space type's lexicon. Locally `PDS_LEXICON_AUTHORITY_DID` (in `docker/.env`, empty in `.env.example`) names `lexicons.test`, whose `com.atproto.lexicon.schema` records `docker/scripts/publish-lexicons.sh` writes from `lexicons/**.json` (space types only). `scripts/dev.sh` runs it on every `up`. A new account's DID gets written to `.env`, followed by a full `compose up -d`; `up -d pds` alone would leave the relay and Jetstream in the old container's network namespace. The PDS caches failed lexicon lookups for 5 minutes, and keeps a resolved declaration in its `account.sqlite` (`lexicon` table) across restarts, granting new sessions' `space:` scopes from that copy; the script drops the copies of what it publishes, so a newly declared collection reaches the next sign-in.
- **Labeler (Ozone).** `ozone` runs the upstream image pinned by digest, in the PDS's network namespace (port 3010, published on `pds`), because its DID document names `http://localhost:3010` and both the PDS (proxying `createReport` for `atproto-proxy: <did>#atproto_labeler`) and the host's AppView (`subscribeLabels`) must reach it there. Its database is a second one, `ozone`, on `appview-db`. `docker/scripts/setup-labeler.sh` (run by `scripts/dev.sh`, safe to rerun) creates `moderation.test` (the service account), `mod.test` (an admin moderator) and `triage.test` (the AppView's member), generates `OZONE_SIGNING_KEY_HEX` (secp256k1), adds `#atproto_labeler` and `#atproto_label` to `moderation.test`'s DID document with a PLC operation signed by the PDS's rotation key (run with `node` in the Ozone image, which carries `@did-plc/lib`), writes `OZONE_SERVER_DID` to `docker/.env` and the labeler DID to `local.properties` (`activitytracker.labelerDid`). Until `OZONE_SERVER_DID` is set the container idles instead of crash-looping.
  - **No local UI.** The image's Next.js UI has `plc.directory` and Bluesky's handle resolver compiled in, so it can't sign in to `.test` accounts. Moderate through the API with Basic auth `admin:$OZONE_ADMIN_PASSWORD` (`tools.ozone.moderation.emitEvent`, `tools.ozone.team.addMember`); the `local-stack` skill has the calls.
  - **Team members** must have a full atproto account document (a handle and an `#atproto_pds`): Ozone verifies service auth with `resolveAtprotoData`. The AppView's `did:web` has no PDS, so it joins as `triage.test` instead (`roleTriage`), whose app password `setup-labeler.sh` writes to `docker/.env` (`APPVIEW_TRIAGE_DID`, `APPVIEW_TRIAGE_PASSWORD`) for the AppView's run task.
  - **Bumping.** Pull the new image and pin its digest; Ozone migrates its database at start (`OZONE_DB_MIGRATE=1`). Then rerun `setup-labeler.sh` and the `local-stack` skill's labeler checks. The daemon (`service/daemon.js`: event push to PDSes, scheduled actions) isn't run.
- **Segment importer.** `docker/scripts/setup-importer.sh` (run by `scripts/dev.sh`, safe to rerun) creates `importer.test` and an app password for it, and writes `SEGMENT_IMPORTER_DID`, `_IDENTIFIER`, `_PASSWORD` and `_PDS_URL` to `docker/.env`; a changed DID restarts the AppView. A reset deletes the account, so `scripts/segment-import.sh` fails to sign in until `dev.sh` runs again.
- **Admin site.** `docker/scripts/setup-admin.sh` (run by `scripts/dev.sh`, safe to rerun) creates `siteadmin.test` and writes `APPVIEW_ADMINS=<its DID>=operator` to `docker/.env` (admin/admin-site); a changed value restarts the AppView, and a reset clears it so the next run writes it again. It signs in with `TEST_ACCOUNT_PASSWORD` through OAuth like any account, so it needs no app password.
- Public requestCrawl rejects `localhost`, so the `relay-crawl` one-shot registers the PDS through the relay admin API (`admin:$RELAY_ADMIN_PASSWORD`).
- **Keep the relay's per-host limits at their defaults.** An untrusted PDS may send 2,600 commits an hour and 21,000 a day (indigo's baseline plus its 100-account limit; `/admin/pds/list` shows them). The segment importer stays under them by writing 100 records to a commit, at most 2,400 commits an hour (`RepoWriter`). Raising them (`/admin/pds/changeLimits`) doesn't speed a commit-per-record writer up safely: the burst overflows Jetstream's per-account verify queue (64 commits), it drops the account's commits and must resync the whole repo by `getRepo`, which times out after 5 minutes for a large repo fetched through the tunnel.
- `docker/.env` holds dev-only secrets and is git-ignored. `.env.example` is the template, so add new variables there.
- `create-account.sh` hard-codes the `app.activitytracker.actor.profile` NSID. Keep it in step with `Nsid.NAMESPACE`.
