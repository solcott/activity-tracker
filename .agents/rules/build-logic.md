# Build

- Convention plugins live in `build-logic/convention`. Feature modules apply `activitytracker.feature.api`, `.presenter` or `.ui` (`FeatureConventionPlugins.kt`), which set up the module's kind, the sibling `-api` (from its own path) and the shared modules, so their scripts hold only extra dependencies. Other client modules apply `activitytracker.kmp.library` or `activitytracker.kmp.compose`, `androidApp` applies `activitytracker.android.application`, JVM modules (`server-appview`) apply `activitytracker.kotlin.jvm`, the web shell modules apply `activitytracker.kmp.web`, `desktopApp` applies `activitytracker.kotlin.jvm` plus the Compose plugins, and the two iOS-only modules (`:iosShell`, `:iosExport`) apply `kotlin("multiplatform")` and `activitytracker.quality` themselves. The Android namespace is derived from the module path. Put shared configuration in a convention plugin, not in module scripts. There is no `subprojects {}`/`allprojects {}`, so don't add one.
- Every module gets `checkModuleBoundaries` from `activitytracker.quality` (`ModuleBoundaries.kt`), wired into `check`: it reads the module's declared project dependencies and fails on a presenter module (`-presenter`, `:app-common-presenter*`) depending on a UI module (`-ui`, `:ui-*`) or the reverse, a feature depending on another feature's non-`-api` module, or an `-api` module depending on anything but `-api`/`:core-*` (dev/module-boundaries). A module's kind comes from its path, so name new modules by those suffixes.
- Every module gets ktfmt (kotlinlang, width 140), detekt with Compose rules and the repo's own rules (`:detekt-rules`, the `activitytracker` rule set in `detekt.yml`) and sort-dependencies from `activitytracker.quality`. `check` runs `detektAll`: the plain task plus the type-resolution ones (`detektMainJvm`, `detektTestJvm`, and `detektMainAndroid` only in a module with `src/androidMain`), which alone see rules that need types (`UnsafeCallOnNullableType`, `UnusedPrivateProperty`). It leaves out detekt's per-source-set tasks (`detektCommonMainSourceSet`, …), which repeat the plain task. A new repo rule goes in `:detekt-rules` with a test using `detekt-test`'s `lint`, and is turned on in `detekt.yml`. The Gradle daemon caches detekt's plugin classloader, so after changing a rule run `./gradlew --stop` before checking it on the modules. Don't scope a rule with `includes`/`excludes` paths: each detekt task (whole module or one source set) matches them against a different relative path, so check the file name in the rule instead (`UseSingleFlight`). Run `./gradlew format` after editing build scripts too, because dependency blocks must stay sorted.
- The root project applies `activitytracker.cpd` (`CpdConventionPlugin.kt`): one `cpdCheck` runs PMD's copy-paste detector over every module's main Kotlin sources (tests and `build/` left out), using the `de.aaschmid.cpd` plugin's `Cpd` task type without applying that plugin, whose `apply` walks `allprojects`. It's report-only (`build/reports/cpd/`) and not in `check` until the existing duplicates are cleaned up; `-Pcpd.fail=true` makes it fail, `-Pcpd.minTokens` sets the threshold (default 100).
- In modules that apply the Compose compiler plugin, `activitytracker.quality` also has one main compilation per module (the JVM target's; wasm in `:webApp`; the iOS simulator's in `:iosExport`, which has the plugin only so Compose copies resources into the iOS app) write the compiler's stability reports to `build/compose/stability`, adds `config/compose/stability.conf`, and wires `composeStabilityCheck` into `check`. The reports are that compile task's declared output (a per-task plugin option, not the Compose extension's `reportsDestination`, which every compilation would write to undeclared), so a build-cache hit restores them. No other compilation writes reports: a composable that exists only in `iosMain`, `wasmJsMain`, `androidMain` or a test source set isn't checked. It fails on any restartable composable param that isn't `stable`. `composeStability { strictClasses.set(true) }` additionally fails on unstable class fields (on in every `-api` module and `:app-common-api`). Fix findings with `@Immutable`/`@Stable` or `ImmutableList`; the conf file is only for types we don't own.
- Project paths are flat (`core/data` → `:core-data`) to avoid empty parent projects. Register a new module in the `listOf(...)` in `settings.gradle.kts`.
- `androidApp` is a separate application module (the AGP 9 KMP split), so it can't use Metro intrinsics. Graph creation is exposed from `composeApp` (`createAndroidAppGraph`).
- Every JVM toolchain is Amazon Corretto 25. Configuration cache, build cache and parallel are on. Keep tasks configuration-cache-safe: no `project` access at execution time, and use `isolated.rootProject` for root files.
- Wasm tests are disabled repo-wide in `KmpLibraryConventionPlugin`, along with the wasm test executable's link (a disabled task still runs its dependencies). `:webApp:check` links the development executable once, so `check` still proves the web app links. Android host tests (`testAndroidHostTest`, commonTest on the Android target) exist only in modules with `src/androidMain` or `src/androidHostTest`. Client modules carry a `jvm()` target so tests run on the JVM. That target is also the desktop app's, so anything contributed to `AppScope` in a `jvmMain` ships in `:desktopApp`. Test-only helpers there are plain classes, not contributions. The hierarchy template adds `commonJvm`, `nonWeb`, `nonAndroid`, `nonApple` (everything but iOS) and `nonMobile` (jvm + web) source sets (`web` is KGP's own), each only in a module that has a `src/<group>Main` or `src/<group>Test` directory: an unused group still costs two source sets with their configurations and tasks. So create the directory first, then sync. Module scripts configure them through the generated accessors, like any target (`nonWebMain.dependencies { ... }`), not `getByName("nonWebMain")`; a module with no sources for a group declares the dependency on each target instead (`:composeApp`'s MapLibre). An `actual` that would be identical on jvm and Android belongs in `commonJvmMain` (or `nonWebMain` if iOS matches too), not in copies.
- iOS test binaries link Swift libraries because cryptography-kotlin uses CryptoKit. The `dev.whyoleg.cryptography` plugin in the library convention handles this. Don't remove it.
- Plugin behaviour is covered by TestKit tests in `build-logic/convention/src/test`. Run them with `./gradlew -p build-logic :convention:test`, and add one when you change a plugin's observable behaviour.
- Dependency versions live only in `gradle/libs.versions.toml`. To find KMP library coordinates or check target support, use the `kotlin-multiplatform-libraries-expert` skill rather than guessing.
- Don't hand-edit `detekt-baseline.xml`. Fix the finding, or regenerate it with `./gradlew detektBaseline` if the user agrees.
