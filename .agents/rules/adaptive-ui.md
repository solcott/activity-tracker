# Theme, adaptive components and navigation shell

Each platform follows its own conventions in one shared UI. `ui/theme` has the brand (teal, amber `tertiary` for likes) as full Material 3 schemes. `AppTheme` adapts it by `LocalUiPlatform`: Material 3 on Android; iOS grouped surfaces, Apple text styles and dimming instead of ripples on iOS; Inter (bundled in `nonMobileMain/composeResources`) and a denser scale on desktop and web. UIKit colours with no Material role (`tertiarySystemFill`, the segment thumb) are `IosColors`, read through `LocalIosColors`; add to it rather than hard-coding a colour in a wrapper.

Screens build from `ui/adaptive` (`AppScaffold`, `AppTopBar` (a `titleMenu` makes its title a picker, like the feed's scope), `AppButton`/`AppSecondaryButton`/`AppTextButton`/`AppIconButton`, `AppTextField`, `AppSegmentedControl`, `AppSwitch`, `AppCheckbox` (`AppTriStateCheckbox` for a partly selected group; expect/actual, a native `UIImageView` with SF Symbols on iOS; content pinned over a scrolling list, like a sticky header, provides `LocalPinnedOverContent` so its marks go over the Compose canvas and rows can't show through), `AppFilterChip`, `AppMenu`, `AppBottomSheet` (with `AppSheetHeader`), `AppDatePickerDialog`, `AppAlertDialog`, `PlatformIcon`, `ReadableList`), never the Material widgets those wrap; detekt's `UseAdaptiveComponents` enforces this. A wrapper that differs by platform is `expect`/`actual`, like `AppCheckbox`: the iOS look in `iosMain` (`Foo.ios.kt`), Material in `nonAppleMain` (`Foo.nonApple.kt`), so neither compiles into the other's build. `AppSegmentedControl` (`UISegmentedControl`) and `AppProgressIndicator` (`UIActivityIndicatorView`, also `AppPullToRefresh`'s iOS spinner, faded on the view since a `graphicsLayer` alpha can't reach it) are native `UIKitView`s; the rest of the iOS actuals are drawn in Compose. Wrappers that only forward to Calf (`calf-ui`) stay in commonMain, since Calf already picks UIKit's native piece: menus, sheets, switches, alerts (`AppAlertDialog` takes any number of actions, through Calf's `AdaptiveBasicAlertDialog`) and the tab bar; `AppDatePickerDialog`'s iOS actual uses Calf's date wheels. A native view normally sits under the Compose canvas and shows through a cut-out, which exposes the window's white behind any translucent part or Compose fill. Both native wrappers therefore set `placedAsOverlay`, which means they draw above Compose content that scrolls over them, including the top bar.

The iOS navigation bar is drawn in Compose, because Calf's native one is pinned to the window and can't follow screen transitions or swipe-back. It is clear at rest and blurs the content scrolled under it with Haze (`AppScaffold` makes the content its source): iOS 26's soft scroll edge effect, or a material and hairline before iOS 26 (`usesLiquidGlass`).

Signed in, `nav/AppShell` wraps the navigable screens. It shows a native tab bar on iOS, floating over the screens so they scroll under its glass (`AppScaffold` pads content clear of it), a bottom bar or rail on Android, and a sidebar on wide desktop and web windows. Each `TopLevelDestination` keeps its own back stack (`resetRoot` with save/restore). `App` tells each screen through `LocalIsNavRoot` whether it is a tab root, which drops its back button and gives it a large title on iOS.

Activity media show through `ui/MediaRow` (the route map, then each photo, in one sideways row, on the feed card and the detail page) and the full-screen `MediaGalleryScreen` (a `HorizontalPager`; tapping a photo zooms it with ZoomImage's `CoilZoomAsyncImage`). Images load with Coil; `App` sets the singleton loader up with `HeldPhotoFetcher`, which serves `heldphoto:` URLs from the signed-in session's uploaded bytes (`HeldPhotos`). The import and edit screens share `ui/ActivityDetailsForm` (title, description, dive site, photos), which compresses each picked photo with `compressPhoto` (WebP through Skia on iOS, desktop and web, `Bitmap` on Android) before it reaches the presenter.

Charts are built on Vico (`com.patrykandpatrick.vico:multiplatform`, every client target) with the shared pieces in `ui/chart`: `StaticChart` (fitted to its width, no scroll, zoom or animation, with a content description), `chartColors` from the theme, `StepConnector`, `WholeRangeXStep` for charts without an x axis, `PointLabels` for value labels kept inside the chart (Vico's own data labels shrink between close points and skip the ends), `TimeSeriesChart` for a value over an activity with y and time axes, and `ZoneBars` for time in zone (plain rows, so each reads as one sentence to a screen reader). Build new charts from these rather than drawing on `Canvas`.
