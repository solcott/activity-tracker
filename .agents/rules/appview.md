# AppView

- **The AppView never writes to repos.** It reads Jetstream and serves `app.activitytracker.*` queries. The exception to "only indexes" is `actor_private_details`: profile details an athlete marks Mutuals or Only me, written with `putPrivateDetails`, because repo records are public.
- **Private details are enforced in views.** Never return a row of `actor_private_details` except through `visibleDetails` (`api/PrivateDetails.kt`): `self` is for the athlete only, and `mutuals` needs follows in both directions. A detail that is also in the public record is public. `deleteActor` deletes the row. Validate with `ProfileDetailRules`: the indexer drops what breaks a rule, and procedures reject it.
- **Activity streams are public records whose visibility holds only in `ActivityStreamsViews`.** Serve them only through `getActivityStreams`, which checks the record's visibility (unknown values mean `self`) and strips zones unless the viewer may see the athlete's training. Their data blob comes through `StreamSource` and is cached by CID in `activity_stream_data`. TODO(spaces) in `BACKLOG.md`.
- **`checkUserAccess` is the managing-app callout.** An athlete's PDS calls it before issuing a credential to one of their `app.activitytracker.space.athlete` spaces. Its tokens are addressed to `managingAppService` (`<serviceDid>#activitytracker_space`), so the route uses the separate managing-app verifier (`verifier.forAudiences`), and AppView tokens never work there or the reverse. `SpaceAccess` decides by tier (`AthleteSpace` skey): `public` admits anyone, `mutuals` uses `isMutual` (the same rule as `visibleDetails`), and everything else, every `write` and an issuer other than the space's authority are denied. A denial is `200 {"authorized": false}`, never an error.
- **Repos are untrusted input.** The `Indexer` decodes with the shared `AtJson` models, drops records that fail to decode (it catches `IllegalArgumentException` and `SerializationException`), and truncates free-text columns with `.take(n)` so they fit the column. New record handlers do the same.
- **Indexing is idempotent.** Every write is an upsert or delete keyed by AT-URI, so rewinding the Jetstream cursor replays safely. Never use a plain `insert` for record rows. Every new record table also needs a delete branch in `Indexer.delete` and a line in `deleteActor`.
- **Recordings (`feed.activity#recordingOf`) are honored only within one author's repo.** The indexer stores `recording_of` only for a link to another of the author's own activities. `shownInFeeds` (`api/Views.kt`) hides a recording from feeds only while the activity it names is indexed and isn't itself a recording, and `hydrate` lists a primary's `recordings`. Queries that look for duplicates (`getAuthorActivitiesByStart`) return recordings too.
- **Activity photos (`feed.activity#media`) are served by redirect.** `boundedPhotos` keeps the `#image` members whose blob is WebP or JPEG, within the lexicon's size, with a real CID (other union members stay in the repo but not the index), and `activity_media` lists them. `GET /img/media/{did}/{cid}` (`api/BlobRedirects.kt`) redirects to the PDS's `sync.getBlob` only for a CID one of that athlete's indexed activities shows, like the avatar route, and `hydrate` builds `ActivityView.media` with those URLs.
- **Don't trust client timestamps for ordering.** Feed order uses `sort_at = min(createdAt, indexedAt)`, so a client can't pin a record to the top by dating it in the future.
- **Migrations.** These are Flyway files in `src/main/resources/db/migration`, named `V<n>__<description>.sql`. Never edit a migration that is already committed. Add the next `V<n+1>`, because the local Postgres has already applied the old one and Flyway rejects a changed checksum. Keep SQL portable: tests run it on H2 in `MODE=PostgreSQL`, so use no Postgres-only types or functions. Timestamps are `BIGINT` epoch millis. SQL that only PostgreSQL can run (extensions, GIN/trigram indexes) goes in `db/vendor/postgresql`, which `DatabaseFactory.migrate` adds for that database only. Its versions share one sequence with `db/migration` (`MigrationVersionsTest` checks).
- **Routes.** Add queries with `xrpcQuery(X.method, verifier) { params, viewer -> ... }` in `Routes.kt`. Auth is optional at that level. Procedures use `xrpcProcedure`, which always requires auth and passes the caller as a non-null `viewer`. Each change only the caller's own data. A handler that needs a viewer throws `AuthException`. Map client errors to `XrpcError(status, "ErrorName", message)`.
- **Tests** (`AppViewTest`) feed `JetstreamEvent.Commit`s into a real `Indexer` over H2 and then read back through `testApplication`. Test new indexing and views the same way, end to end.
