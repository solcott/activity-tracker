# Activity files

`core/activityfile` (`:core-activityfile`) reads FIT, GPX, TCX and Shearwater dive (XML) files and UDDF and Subsurface (`.ssrf`/XML) logbooks, optionally gzipped, into `ImportedActivity`s (`ActivityFileReader.read` returns a list: one per file, or one per dive in a logbook), which `ActivityDraft.fromImport` publishes like a recording (its GPX track a `feed.activityTrack` in the athlete's `self` space, `ActivityTrackStore`). Every sample's channels (indoor ones too, plus gear changes) become `ImportedActivity.streams` through `StreamBuilder`, in the lexicon's integer units: besides the motion channels, a dive's ppO₂, CNS, N₂ load, NDL, deco stop depth and time (null outside deco), time to surface and per-tank pressure (`tankPressures`, each tank's readings placed on the nearest sample within 30 s, in `dive.tanks` order), a run's respiration rate and running dynamics, and left/right power balance. The channel list is `ActivityStreamData.INT_CHANNELS` (`core/lexicon`), which `halved()`, `ActivityMerge` and the AppView's `bounded` iterate, so a new int channel joins that table. Gas switches (`gasSwitches`, the gas named as oxygen and helium percents; the first gas is a switch at 0, repeats dropped) and laps (FIT sessions only, not TCX; a single lap spanning the activity isn't kept) sit beside them like `gears`; a phone recording gets distance, altitude and speed streams from `StreamBuilder.fromLocations`. They publish as a `feed.activityStreams` record under the activity's rkey (see `ActivityStreamsStore`). `ActivityFileReader` is the entry point: it picks the format from the content, not the file name. GPX, TCX, Shearwater, UDDF and Subsurface XML parse in common code with xmlutil's pull parser (`walkXml` matches local names, so namespace prefixes don't matter); the dive logs share `DiveLogs` (summary, sub-sport, device name, gases) and skip an undated dive rather than fail the logbook. Dive-log times have no zone (`parseLocalDateTime`): they're read in the device's zone (`TimeZones.device()`), `ImportedActivity.localStart` keeps the clock, and the import screen warns and lets the athlete pick the dive's zone (`inZone`; web bundles `@js-joda/timezone` for the zone rules). A dive's depths, gases, CNS, tanks and site come through as `ImportedDive`, from Shearwater files and FIT dive logs alike. Every decoder and parser keeps when each gas was switched to (`DecodedActivity.gasSwitches`): FIT `dive_gas_switched` events (their gas index resolved by `FitDives.gasSwitches`, which drops switches to unknown slots), Subsurface `gaschange` events, UDDF `switchmix` and Shearwater's per-sample gas fractions. FIT `tank_update` and UDDF `tankpressure` readings come through as `DecodedActivity.tankUpdates`, told apart by sensor (FIT tanks are ordered by `tank_summary` sensor). UDDF also gives waypoint ppO₂, CNS, no-deco time, deco stops and heart rate, the dive's air temperature, visibility, altitude, no-fly and desaturation times and highest ppO₂, each tank's volume and gas, and the diver's notes, which seed the import screen's description for a single file (a logbook batch drops them, since the athlete never sees them). A FIT activity's calories, training effects, power, cadence, descent, shift counts and mountain bike dynamics publish on the record; its training load (FTP, IF, TSS, training effects) goes on the zones record (`ActivityZonesStore.put`), never the public activity. A dive with no GPS track keeps its entry and exit (or the logbook site's position) as a GPX track in `self`, with no polyline. A logbook's dive site name comes through as `ImportedDive.siteName` and lands in `ActivityDive.site` (the name only: its coordinates, `entry`/`exit`, stay out of public records), which the athlete can change on the import screen or later with Edit. `DiveSummary.of` turns the rest into `ActivityRecord.dive` in lexicon units (cm, tenths of °C, seconds, mbar, mL), and the dive's page and feed card show those figures (`ui/DiveStats.kt`) instead of distance and pace. A dive logged before that falls back to its depth chart for depths. Each FIT decoder passes its SDK's dive messages through as `FitDiveMessages`, and `FitDives` (common) picks the session's summary and the gases breathed. FIT uses Garmin's own SDK on each platform behind the `FitDecoder` interface: the Java SDK on Android, desktop and the AppView (`commonJvmMain`), the npm JS SDK on web (`@JsModule` externals), and the Swift SDK on iOS. Kotlin/Native can't call Swift, so `iosApp/iosApp/SwiftFitDecoder.swift` implements the interface and `ContentView` passes it into `IosAppGraph.Factory`. `gunzip` and `gzip` are expect/actual over each platform's built-in zlib (`java.util.zip`, iOS zlib, the browser's `DecompressionStream`/`CompressionStream`). `ActivityFileReader.readFile` also reports the file's `ActivityFileFormat` (each carries its `feed.activitySource#format` token) and whether it came gzipped (`ImportedFile`); `read` is `readFile(…).activities`. Every format decodes to a `DecodedActivity`, and `DecodedActivityMapper` (common) interprets it. A logbook of several dives shows on the import screen as a `DiveBatch` to pick from (all selected at first, one zone for the file), and `ActivityRepository.publishAll` queues the picked dives before draining the outbox once.

**Originals.** Every imported file is kept as is (`feed.activitySource` in `self`, `ActivitySourceStore` in `core/data`). `SourceFile.prepare(bytes, fileName, file)` gzips the picked bytes unless they came gzipped (`compressed` says which), returns null when the stored form passes 10 MB (the import screen then says the original won't be kept), and gives a random `key` that every draft read from the file shares, so a logbook is stored and uploaded once (each dive's record names its `entry`, in file order). `SourceFile.original(stored, compressed)` gives back the picked bytes for download.

**Export.** The module also writes GPX, TCX, FIT and, for dives only, UDDF for the owner's Export action (`ActivityExporter` in `core/data`; `formats(…, isDive)` offers UDDF wherever it offers TCX on a dive). `ExportPoints.join` joins the stored track and streams on their second into an `ExportActivity` in SI units (the reverse of `StreamBuilder`), and `GpxWriter`/`TcxWriter` serialize it with `buildString` (GPX: Garmin `TrackPointExtension` v2 plus a bare `<power>`; TCX: one lap, `TPX` speed, run cadence and watts). Numbers go through `toXmlDecimal`, never `Double.toString`. Tests round-trip each writer through `ActivityFileReader`. `FitWriter` writes FIT in common code (`FitOutput`: header, definitions, little-endian fields, CRC), unlike decoding, which uses each platform's SDK: the file holds only messages we choose, with field numbers and scales from Garmin's profile (`FitProfile`), and jvmTests check it by decoding with the Java SDK. It writes one record per whole second (the first point in it, with every stored channel, deco state and running dynamics included), gear changes as events, and a dive's settings (with water type and density), gases (the record's, then any a switch names that it doesn't), a `dive_gas_switched` event per switch naming its gas slot, a `tank_update` per tank reading (tank n is sensor n + 1, as on its `tank_summary`) and `dive_summary`. Stored laps become lap messages, or one lap spanning the activity when none are stored; the session carries the record's totals and, as only the owner exports, the zones record's training load (`ActivityExporter` reads it from `getActivityStreams`). A re-imported FIT gives back every gas, switch, lap and channel. `UddfWriter` (common, `buildString`) writes a UDDF 3.2 logbook of one dive: the record's `device` as the diver's dive computer, the site (`dive.site` and the first positioned point's coordinates, which only the owner's export carries), a `mix` per gas (the record's, then any a switch or tank names that it lacks; ids from the percents, `mix-21-0`), then one repetition group and dive with `informationbeforedive` (datetime in the zone `ActivityExporter` passes, `TimeZone.currentSystemDefault()`, as a zone-less local time), a waypoint per second with a depth (the first point in it, so an entry and exit track adds none) carrying every stored dive channel, `switchmix` at the first waypoint at or after each switch, its `tankdata` (`tankN` in `dive.tanks` order, which waypoint `tankpressure` refs name, then a gas-only `tankdata` per mix no stored tank holds: Subsurface makes cylinders only from tanks in a namespaced file; `UddfParser` skips such tanks). Subsurface's `uddf.xslt` can't resolve a namespaced file's `switchmix` gas or `divemode`, so it shows the gases but not which one each switch went to, nor CCR mode; the file keeps the UDDF namespace anyway and `informationafterdive`, in SI units. A dive stored without switch times switches to its first gas at the start and only defines the rest. Children follow the 3.2 schema's sequences, which a jvmTest (`UddfSchemaOrderTest`) checks per parent; `heartrate`, which the 3.2.1 schema lacks, goes after `divetime`. `UddfWriterTest` round-trips through `ActivityFileReader`. `FitSports` maps activity types to FIT sport and sub-sport, the reverse of `DecodedActivityMapper.activityType`, and a test checks each entry imports back as its type. `Gpx.write` in `core/location` stays the track blob's writer and doesn't change.

**Duplicate dives.** The import screen loads the athlete's dives from a day either side of the file's (`FeedRepository.ownActivitiesStartedBetween`: the AppView's `getAuthorActivitiesByStart` plus outbox writes it hasn't indexed) and `DiveMatcher` (`core/data`) flags each imported dive that overlaps a logged one by half the shorter, is the same length a whole number of hours off (a zone mix-up), or repeats an earlier dive in the file. Duplicates start on `DuplicateAction.Ignore` (unchecked; Select all skips them) with a warning, and the athlete can import anyway, `Merge` into the logged dive (`ActivityRepository.mergeInto`, `ActivityMerge`: fills only fields and stream channels it lacks; an outbox-pending activity gets only its record merged; picking Merge loads the logged dive's streams so the note says whether charts are added, and `FeedRepository.rewrites` shows the merged record over the AppView's until Jetstream brings it), or `Group` it as another recording (`feed.activity#recordingOf`, an at-uri, so feeds show the dive once and its page lists the recordings). A recording of an in-file dive publishes after it, pointing at its URI. On its page, the owner can delete an activity (`ActivityManager.delete`, confirmed in an `AppAlertDialog`): a main activity's recordings go with it or, if the athlete chooses, are split off first (`recordingOf` cleared) so none points at a deleted activity. A group of exactly two (the main activity and one recording) can be ungrouped from either page (`ActivityManager.ungroup`); a larger group can't, though any of its recordings can be deleted from its own page.
