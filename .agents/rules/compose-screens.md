# Screens, Circuit and Metro

Use the `new-screen` skill to scaffold a screen. The rules it follows:

- A screen is a `@CircuitSerializable(<scope>::class) data object/class XScreen : Screen`, plus an `XState : CircuitUiState` with an `eventSink`, an `XEvent` sealed interface, a presenter and a UI. Screen args must be serializable: pass IDs and AT-URI strings, not views.
- Use the same scope in `@CircuitSerializable` and both `@CircuitInject`s. `SessionScope` is for signed-in screens. `AppScope` is only for signed-out ones such as login. A mismatched or missing registration compiles fine but crashes at runtime the first time navigation state is saved.
- The presenter is a `@CircuitInject(XScreen::class, <scope>::class) @Composable fun XPresenter(screen, navigator, ...deps): XState`. Circuit supplies `screen`/`navigator`, and Metro injects the rest. Don't write a presenter class with `@AssistedInject`. A class with plain `@Inject` is fine only when it needs neither screen nor navigator (like `LoginPresenter`).
- The UI is `@CircuitInject(XScreen::class, <scope>::class) @Composable fun XUi(state: XState, modifier: Modifier = Modifier)`.
- **One screen spans three modules, all in the same feature package `io.github.solcott.activitytracker.app.<pkg>`:** `XScreen.kt` (Screen, State, Event) in `feature/<pkg>/api`, `XPresenter.kt` in `feature/<pkg>/presenter`, and `XUi.kt` in `feature/<pkg>/ui`, each module's script only `plugins { id("activitytracker.feature.api|presenter|ui") }` plus any other feature's `-api` it opens. Features not moved yet keep the old split: `app/screens`, `app/presenters` and `composeApp`, in the same packages. Presenters and UIs see each other only through the contracts. Presenter modules have the Compose runtime and foundation, but only for `TextFieldState`: no material3 and no UI code (layouts, modifiers, emitting composables). `composeApp`, `webApp` and `desktopApp` depend on presenter and UI modules only so their graphs aggregate the factories; a new feature's `-presenter` and `-ui` join their dependencies. Never import a presenter from UI code; `checkModuleBoundaries` fails a presenter module depending on a UI module (or the reverse) and a feature depending on another's presenter or UI module (dev/module-boundaries).
- **Shared code has one home.** Whatever two features use goes to the shared module for its layer, never a copy: contracts (`UiError`, visibility, route and details-form types) to `app/common/api`, presenter helpers (`rememberSingleFlight`, `DetailsForm`, `uiErrorOf`, `rememberReporting`, …) to `app/common/presenter`, domain composables (`ActivityCard`, `ActivityMap`, `VisibilityPicker`, `startTime`, …) to `app/common/ui`, design-system pieces with no app types (`ui/adaptive`, theme, charts, `TestTags`) to `ui/designsystem`. Same package as before; make a moved `internal` public. `ActivityTypePicker` and `expect` UI helpers (`LocationPermission`) stay in `composeApp` until record moves.
- **Text fields** take a `TextFieldState`, never the `value` + `onValueChange` overloads (`String` or `TextFieldValue`). When the presenter needs the text (to save, validate or search), it owns the state: `rememberTextFieldState()` in the presenter, a `TextFieldState` field in `State`, no `XChanged(String)` event. The presenter reads `.text` when it acts, fills a loaded value with `setTextAndPlaceCursorAtEnd` and empties it with `clearText`; tests edit the state the same way. Reading `.text` in a `State` getter (`valid`) or in the presenter's composition keeps it live. Text only the UI uses (a picker's search box) is a `rememberTextFieldState()` in the UI. A `readOnly` field showing a value takes `rememberReadOnlyTextFieldState(text)` (`ui/`). Use `lineLimits = TextFieldLineLimits.SingleLine` and `onKeyboardAction`, not `singleLine`/`keyboardActions`, and an `InputTransformation` to react only to typing (opening a menu). detekt's `UseTextFieldState` rule (`:detekt-rules`) enforces this; it can't see types, so name every argument after the state.
- **Platform look.** Build UIs from `ui/adaptive` (`AppScaffold`, `AppTopBar(title, onBack = ...)`, `AppButton`, `AppTextField`, `AppMenu`, `AppIconButton(AppIcon.X, ...)`…), not Material's `Scaffold`, `TopAppBar`, buttons, text fields, progress indicators, sheets or dialogs; detekt's `UseAdaptiveComponents` flags those. Give a screen `onBack` even if it can be a tab root: `AppTopBar` hides the button at the root (`LocalIsNavRoot`). Lists go in `ReadableList` (centred column and scrollbar on desktop and web), and scrolling forms take `Modifier.readableWidth()` inside a `ScrollbarBox`. Pass `AppScaffold`'s padding to them as content padding (`ReadableList(contentPadding = padding)`, or `.padding(padding)` after `verticalScroll`), never as a `Modifier.padding` around the scroll, so content scrolls under the bars. A scrolling screen also gives its bar a `rememberAppTopBarScrollBehavior()` and puts its `nestedScrollConnection` on the `AppScaffold` (on the list, inside pull to refresh): the bar then marks content scrolled under it, and a tab root's large title collapses on iOS. Branch on `LocalUiPlatform` only for real differences in behaviour, like pull to refresh on phones or Android's Record FAB. A new full-screen flow also joins `TopLevelDestination.FullScreenFlows`.
- **Text.** Every string a UI shows (labels, content descriptions, units, counts) lives in `ui/resources/src/commonMain/composeResources/values/strings.xml` (`:ui-resources`, which every UI module and app shell depends on) and is read with `stringResource`/`pluralStringResource` from the generated `io.github.solcott.activitytracker.composeApp.resources.Res` (the package it kept when it moved out of `composeApp`). Use `<plurals>` for counts. Shared helpers: `sportLabel`/`activityTypeLabel` (looked up by token as `sport_<token>`/`sub_sport_<sport>_<token>`), `handleLabel` (`ui/Labels.kt`) and the composable unit formatters in `Format`. Presenters can't read resources, so a failure goes in `State` as a `UiError` (`:app-common-api`), never a `String`: `UiError.of(kind, cause)` keeps what failed and why (`reason`, a `DataError` from `toDataError`), never the exception's message. Add a `UiError.Kind` and its string, and the UI shows it with `errorText`, the one renderer for every error (ui/error-messages): the kind's text, plus offline, server or unreadable when the reason is one of those.
- Metro generates the Circuit factories (`metro.enableCircuitCodegen=true`). There is no Circuit KSP processor, so don't add one.
- **Shared pieces of a screen.** Presentation logic that several screens repeat lives in one owner, so a host only places its state:
  - **A sub-state with its own sink.** A field of `State` (`@Immutable`, in `:app-screens`) carries an `eventSink` for its own event, and the holder that owns it fills the sink with `::onEvent`: `ActivityDetailsFields` (`DetailsForm`), `VisibilityFields` (`NewActivityVisibility`, `EditVisibility`, `DefaultVisibilitySettings`) and `ActivityTypeField` (`ActivityTypeChoice`). The host declares no event and adds no `when` branch; the shared UI sends to `fields.eventSink`. Default the sink to `{}` so a `State` default can be built.
  - **A host-wrapped shared event** when handling it needs the host's `Navigator`: `ActivityListEvent`, wrapped as `FeedEvent.Activity(...)` and handled by `rememberActivityListEventSink(navigator, activities, onError)`.
  - **Producers.** Most are a `@Stable` holder plus a `@Composable rememberX(...)` that takes its repositories as arguments (`rememberNewActivityVisibility`, `rememberApprovesFollowers`). When a producer would only pass a repository through, make it an unscoped `@Inject` class with a `@Composable produce(...)` that Metro injects into the presenter instead (`ActivityTypeChoices`).
  - **Cursor lists** use `rememberRetainedPaging(key, idOf = …, onKeyChange, enabled, initial) { cursor -> flow { emit(repo.xPage(cursor)) } }` (`uistate-circuit`, ui/content-loading) over a repository's `Outcome<Page<T, M>>` read, and put its `PagedState` in `State` whole. It keeps the items through a failed refresh or page, retries only what failed, shows the pages at once on return, and de-duplicates by id. A new key keeps the old items until it answers (`KeepItems`, search) or clears them. The host edits the items with `update {}` after a write and keeps an action's failure in its own `UiError`, never in the load's status. The UI lays the list out with `LoadMoreAtEnd`, `pagedRefreshStatus` and `pagedFooter` (`ui/PagedList.kt`), which say why through `errorText`. A nested list (a thread's replies) gets one holder per parent inside `key(parent.id)`, seeded with `initial`.
  - **Choose a SubCircuit instead** only when the child needs nothing pushed from the host after it's created: a SubCircuit sees the host only through its screen, and a new screen remounts it. The type picker isn't one because import sets the type from the file.
- **Sub-screens (SubCircuit).** For a reusable piece of a screen with its own presenter and UI (a filter bar, a picker), use `circuitx-subcircuit`, not a screen or a plain composable. It is opted in module-wide (`ExperimentalSubCircuitApi`). The session's `SubCircuit` is built from Metro-multibound `SubPresenterFactory`/`SubUiFactory` sets (`CircuitBindings.kt`) and provided as `LocalSubCircuit` in `App.kt`. There's no `AppScope` one yet. It spans the same three modules and package as a screen:
  - **Contract** (the feature's `-api`, or `app/screens`): an `@Immutable` `XScreen : SubScreen<XOuterEvent>`, an `XState : SubCircuitUiState` with an `eventSink`, an `XEvent` and an `XOuterEvent : SubCircuitOuterEvent` sealed interface. The screen carries only initial config, never live state: `SubCircuitContent` remembers the presenter per screen and keys its content on it, so a changed screen remounts the child and drops its state.
  - **Presenter** (the feature's `-presenter`, or `app/presenters`): a `@SubCircuitInject(XScreen::class, <scope>::class) @Inject class XPresenter(screen: XScreen, ...deps) : SubPresenter<XOuterEvent, XState>`, a class because SubCircuit has no function form. Metro injects the screen (leave it out if unused); no `@AssistedInject`. There's no navigator. It seeds its state from the screen (`rememberRetained { mutableStateOf(screen.initial) }`) and reports it with a keyed `SideEffect(value) { outerEventSink(...) }`, which also fires when first shown, so the host matches it even after one side lost its state.
  - **UI** (the feature's `-ui`, or `composeApp`): a `@SubCircuitInject(XScreen::class, <scope>::class) @Composable fun XUi(state: XState, modifier: Modifier = Modifier)`, the same function form as a screen's UI. `SessionPreviewSubUis` (`composeApp`, the module that sees every feature UI) registers it for `AppPreview` with `SubUi<XState> { state, modifier -> XUi(state, modifier) }`.
  - **Host**: `SubCircuitContent(state.xScreen, outerEventSink = { state.eventSink(Event.XChanged(it...)) })` in the UI. The host presenter creates the screen once (`rememberRetained { XScreen(initial) }`) and keeps what it needs from outer events in its own state; it replaces the screen only to reset the child. Parent and child talk only through the screen (down) and outer events (up).
  - **Tests**: `circuitx-subcircuit-test`'s `presenter.test { awaitItem(); outerEvents.awaitEvent() }` in the presenter module's `src/jvmTest`.
- **Event-driven work goes through `rememberSingleFlight()`** (`:app-common-presenter`), never a bare `rememberCoroutineScope()`: `flights.launch(key) { ... }` drops a repeat while the first runs, so a double tap can't save, follow or like twice. The key is the event (`XEvent.Save`, `XEvent.Changed::class` for one with args) or what it acts on (an activity's URI for its like). Derive a `saving`/pending flag from `flights.isRunning(key)` instead of a separate `var`, and use `launchLatest` only when a newer request should replace the running one (a new file pick). detekt's `UseSingleFlight` rule flags `rememberCoroutineScope()` in `*Presenter.kt`. A presenter test for a write sends the event twice while the first is in flight (gate the fake's response) and asserts one write (`ProfilePresenterTest`).
- **Loaded content is a `ContentState`** (`io.github.solcott:uistate`, ui/content-loading). The presenter collects the repository's `Flow<Outcome<T>>` with `produceRetainedContentState(initial, retryKey) { … }` (`uistate-circuit`), or `produceRetainedContentStates(contentStatesOf(…), retryKey) { combineOutcomes(…) }` for several sources (`SegmentPresenter`), and puts it in `State` whole; a Retry or Refresh event bumps the key, which restarts the stream under the same state, so content stays on screen. Key it with `key(…)` instead when a new parameter must not show the old one's content (`FeedPresenter`'s filter). Retained, it shows at once when the athlete comes back. The UI draws it with `ContentStateLayout(state.content, UiError.Kind.LoadX, onRetry)` (first-load spinner or failure) and a `RefreshStatus` item over loaded content, which say why through `errorText`. Check `hasLoaded`, never emptiness or null, for whether anything has loaded. `UiError` stays for actions.
- Wrap suspend calls in `runSuspendCatching`, not `runCatching`, so cancellation propagates. Writes go through repositories (`ActivityRepository` → outbox), never straight to XRPC from a presenter.
- **Graphs.** `AppScope` is app-wide. `SessionScope` is the `SessionGraph` extension created per signed-in account (`key(did)` in `App.kt`). The concrete `@DependencyGraph`s are `AndroidAppGraph`/`IosAppGraph` in `composeApp` platform source sets and `WebAppGraph` in `webApp`. A module that declares a graph needs every contributing module (including `:app-screens`, `:app-presenters` and each feature's `-presenter` and `-ui`) on its compile classpath. `androidApp` can't use Metro intrinsics; it calls `createAndroidAppGraph` from `composeApp`.
- **Stability.** Every `State` is `@Immutable`, and its collections are `ImmutableList` (kotlinx-collections-immutable; convert with `toImmutableList()` where the presenter loads them), never `List`. Models from non-Compose modules that a UI shows (lexicon views, `AuthCoordinator.Status`) carry `@Immutable` from `androidx.compose.runtime:runtime-annotation`. Composable params must be statically stable, so pass `ImmutableList`s and annotated types, not `List`, `vararg` or plain interfaces (`@Stable` it if one must be a param, like `AppGraph`). `composeStabilityCheck` (part of `check`) enforces this from the compiler reports in `build/compose/reports`; `:app-screens`, `:app-common-api` and every `-api` module also run it in strict mode, which fails on any field that isn't statically stable.
- **UI tests, previews and samples** (dev/ui-test-harness). A UI renders from its `State` and values a test or preview sets, never from the machine: read the time from `LocalClock` and the zone from `LocalTimeZone` (`ui/Format.kt`), never `Clock.System` or `TimeZone.currentSystemDefault()` (detekt's `NoSystemClockInUi` flags those in `*Ui.kt`), and the 12/24-hour clock through `uses24HourClock()`, which prefers `LocalHourClock`. `AppTheme` takes `darkTheme`. Under `LocalInspectionMode` maps draw `RoutePreview` and Coil images the preview handler's placeholder, so keep new map or image code behind those. `AppPreview` (`:app-common-ui` `ui/preview/`) renders any UI with no session or network, in a chosen platform look, theme, units, `WindowWidth`, time, zone and clock style, and with the real sub-screen UIs when given `subUis = SessionPreviewSubUis` (`composeApp`; the screenshot suite's `ScreenPreview` passes it). It's production code, because `:androidApp`'s screenshot tests use it. Sample states live in `:app-fixtures` (`app/fixtures`, contracts and lexicon only): `fake…` lexicon builders with fixed defaults (`Fixed.NOW`), `ContentStates`/`PagedStates`, and an `XSamples` object per screen in its feature package, with an `all` map keyed by `SampleKind`. UI tests are `runComposeUiTest { setContent { AppPreview { XUi(XSamples.loaded) } } }` in the UI module's `src/jvmTest` (`composeApp/src/jvmTest` for an unmoved feature, with `subUis = SessionPreviewSubUis` where it embeds sub-screens), and find the shared loading pieces and the back button by `TestTags` (`useUnmergedTree = true`), not by text. A new screen ships its samples and a UI test, and a content-loading one joins `ContentLoadingConformanceTest`, which fails for any `State` with a `ContentState` or `PagedState` missing from its table.
- **Screenshot tests** (dev/screenshot-tests). `:androidApp`'s `screenshotTest` suite (AGP test suites, Compose Preview Screenshot Testing, rendered by layoutlib on the host) holds a `XScreenshots.kt` per screen and sub-screen in `androidApp/src/screenshotTest/.../screenshots/`: the loaded sample at `@PreviewScreenSizes` and `@PreviewScreenVariants`, and its other samples at `@PreviewPhoneSize` through an `OtherSamples` provider, all inside `ScreenPreview` (`AppPreview` sized by the preview). Shared components (adaptive controls, loading pieces, charts) render at `@PreviewComponentVariants` in `ComponentPreview`. `check` compares them with the references in `androidApp/src/screenshotTestDefaultDebug/reference`; a change that alters a screen's look reruns `./gradlew :androidApp:updateDebugScreenshotTestDefaultTestSuite` and commits the changed references with it, after looking at them. `ScreenshotCoverageTest` (composeApp jvmTest) fails for a `@CircuitInject` or `@SubCircuitInject` UI, in `composeApp` or any `feature/*/ui`, without its file; a feature's UI module joins the screenshot suite's dependencies. Layoutlib can't render native views, so new map or platform-view code needs an inspection-mode fallback.
- **Tests.** Presenter tests live in the presenter module's `src/jvmTest` (`app/presenters/src/jvmTest` for unmoved features) and use `Presenter.test {}` or `presenterTestOf` with a Room `inMemoryDatabase()` and a Ktor `MockEngine` (see `LoginPresenterTest`). Use the repo's own (`PresenterTest.kt` in `:app-common-presenter-testing`, which the presenter convention adds to `jvmTest`; root package, no import), never `com.slack.circuit.test`'s: circuit-test composes the presenter on whichever thread resumed it (Room's, Ktor's), racing the test thread, which flakes under load. A reload's loading state shows only if a frame lands before the fake answers, so a test that waits for it after a Retry or Refresh gates the fake (`SessionTestFixture.gate`); otherwise it waits for the state that follows.
